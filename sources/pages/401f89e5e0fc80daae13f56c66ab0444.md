## 2. Target structure and ownership

### Recommended structure

The existing dutch study page becomes the home/index. A **Hoofdstukken** database holds eight records, each already a full page; do not create a separate subpage and database row for the same chapter. A **Grammatica** database holds reusable topic pages and the writing aid. Keep **Lijst onregelmatige verba** as one shared reference page linked from Perfectum and the home.
The existing Todo List remains the task system. This Tier 3 page holds the migration plan; chapter-specific study gaps can become tasks later when they need action.

### Alternatives considered

**Plain subpages:** easier initial setup, but status and cross-references remain manual.
**Two related databases — recommended:** supports chapter filters and reusable grammar with modest maintenance.
**Fully normalized system with photo, vocabulary, and exercise databases:** offers more granular counts but adds capture work; defer until there is a repeated need.

### Hoofdstukken properties

## 6. Acceptance checks and risks

### Definition of done

- [x] **Content preserved:** eight unique chapter records; vocabulary, examples, tips, tables, prompts, and all 17 original images accounted for.
- [x] **Reusable references work:** canonical grammar explanations, two-way chapter links, irregular-verb reference, and writing-plan sync all verified.
- [x] **Index works:** gallery and incomplete-content views reflect actual properties; photo counts match attachments; chapter order is stable.
- [x] **Tracking is truthful:** migration and content completeness are separate; task summaries are configured as native rollups; no unverified Status/Priority/Due automation is claimed.
- [x] **Cutover is recoverable:** source snapshot retained, obsolete indexes replaced only after checks, unresolved content gaps remain visible.

### Failure handling

**Missing photos or exercises:** retain the placeholder and precise gap; do not mark supplied content complete.
**Broken attachments during transfer:** stop that chapter’s cutover, retain the source image block, repair and recheck before clearing its migration flag.
**Formula, rollup, or synced-block limitation:** document the unsupported step and use an explicit temporary manual field or canonical link. Keep the related acceptance item open.
**Duplicate grammar:** compare variants, preserve distinct examples, then choose one canonical explanation; do not discard useful differences simply to deduplicate.
**Scope growth:** add photo/exercise databases or property-writing automations only after the core workflow demonstrates a repeated need.
